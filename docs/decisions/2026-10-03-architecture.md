# 決定：全体の構成と技術選定

- Status: accepted by the owner, 2026-10-03
- 根拠: `docs/research/2026-10-03-consolidated-report.md`（8 本の調査の統合）

## Problem

エディタで関数を指すと、各行が何をするか、具体的な値でどう動くか、同時に来たら何が起きうるかを解説する道具を作る。対象言語は多岐にわたり、ファイルを開いたときに出て、VS Code・Neovim・HTML に出し、他の人に配布する。実際には実行しない。この要件で、部品ごとの技術を決める必要があった。

## Decision

1. **構成**：エディタの外で動く 1 つのバックエンド（Rust、単一バイナリ）と、薄いエディタ拡張（VS Code は TypeScript、Neovim は Lua）。HTML は同じバイナリのサブコマンドが束の JSON から描く。
2. **接続**：LSP の枠を使い、標準に無い画面（行末注釈、シナリオ表示）は `codeReading/` 名前空間の独自メソッドで渡す（Copilot 型）。
3. **バックエンドの言語**：Rust。
4. **多言語の構造**：tree-sitter の文法と tags クエリをバックエンドに同梱する。エディタの言語サーバーの call hierarchy は「あれば使う」任意の強化層。言語を足すのは、文法とクエリを同梱リストに足すことで済ませ、コードを書かない。
5. **描画**：画面の仕様は両エディタで同じ（全行の行末に短い 1 文、全文は hover）。内部では、Neovim は全行ぶんを一度に永続 extmark で付け、VS Code は見えている行 ± 余白にだけ decoration を付けてスクロールで付け替える。
6. **開いたときに出る**：3 層。(a) tree-sitter から機械的に分かる構造の事実を即時に、(b) 保存済みの解説を即時に、(c) 新しい解説は見えている関数から順に生成して関数ごとに貼る。
7. **キャッシュ**：鍵は関数本体のハッシュ + モデル名 + プロンプトの版。保存先は利用者のキャッシュ領域。先読みは開いているファイルだけ。
8. **根拠の表示**：構造の事実と LLM の推論を色で分け、推論には前提を付ける。同時実行の解説は推論のまま出す。将来、安く裏付けられる言語（Go の race detector など）だけ実行を足す余地を、解説の 1 文ごとに根拠の種類を持たせる形で残す。
9. **対応しないもの**：ブラウザ版 VS Code（vscode.dev）。Neovim への wasm や FFI での組み込み。
10. **配布**：Neovim のプラグインは GitHub Release からプラットフォーム別のバイナリを取得し SHA-256 で検証する。VS Code はプラットフォーム別 VSIX にバイナリを同梱する。

## Alternatives considered

- **バックエンドを Go で書く**：tree-sitter の Go バインディングが 2025-11 で停止、CGO でクロスコンパイルが面倒。却下。
- **TypeScript で書く**：Neovim の利用者に Node を要求するか 63 MB の単一バイナリになる。却下。
- **Zig で書く**：tree-sitter のバインディングはあるが、LSP・HTTP・JSON の実績を調べていない。所有者が Rust を選んだため追加調査はしない。
- **独自の JSON-RPC**：Cody と Continue の形。接続のライフサイクルをエディタごとに手書きする。却下。
- **エディタの言語サーバーや利用者の tree-sitter パーサに頼る**：言語と環境で結果が変わる（ruby-lsp と Sorbet は call hierarchy を拒否、Neovim の同梱パーサは 7 種）。任意の強化層に格下げ。
- **Rust を cdylib にして Neovim に読み込む**：クラッシュが Neovim ごと起きる報告が複数。計算量もそれを要しない。却下。
- **wasm**：Neovim にホストが無い（「Not planned」）。VS Code では 15 倍遅い。却下。
- **実行して裏付ける**：多言語と「開いたら出る」の両方と衝突する。v1 では外す。
- **リポジトリ全体の事前計算**：要件に反する。却下。

## Consequences

- Rust の作業は、tree-sitter の同梱、LLM 呼び出し、関数単位のキャッシュ、LSP サーバ（tower-lsp-server）の 4 つに絞られる。
- 言語を足すコストは文法 1 つと tags クエリ 1 本。tags に `@reference.call` が無い言語（C、C++、C#、Swift、Zig）は呼び出し元を字句一致で補う。
- 初回に開いたときは、構造の事実だけが即時に出て、LLM の解説は数秒〜数十秒かけて埋まる。これは LLM の速度の制約で、設計では消せない。
- 解説の 4 割前後は間違っている前提（CRUXEval 44〜63%、DRPBench F1 75%）で、根拠の色分けと前提の表示を省かない。
- 2026-09-30 までに作った Go の題材（`testdata/`）と実行まわりの記録は、実行を外したので削除・参考扱いにする。
