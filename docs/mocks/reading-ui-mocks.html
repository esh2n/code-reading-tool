コードを「動き」で読む画面

インライン注釈を土台に、詳細パネルとシナリオモードを重ねる設計です。同じデータを Neovim、VS Code、HTML に出します。題材は gin の (*Context).Copy の修正前の版です。この版には、実際にデータ競合のバグがありました（修正は PR #1841）。

モックです。行番号、race の報告、実行回数、値は説明用で、実際に実行した結果ではありません。

1インライン（いつも出ている）

行ごとに「この行が何をしているか」を行末に出します。実行で確かめた説明には根拠のシナリオが付きます。確かめていない説明は、推測と分かる色で出します。

K 詳細パネル<leader>cs シナリオモード]d 次の問題（race）へ<leader>ct 注釈の表示を切り替え

2詳細パネル（知りたいときだけ）

行の上で K を押すと開きます。その行の詳しい説明、根拠になったシナリオの結果、race の 2 か所を出します。

3シナリオモード（別のバッファ）

1 つのシナリオを選ぶと、左のコードで通った行だけが明るくなります。右のバッファには、そのシナリオで起きたことが順に並びます。race もシナリオの中の出来事として出ます。

]s [s シナリオを切り替え<CR> その行へo テストの出力t 生成されたテストを開くr 再実行

4VS Code でも同じ

データは同じで、見た目だけ VS Code の部品に置き換えます。行末の説明は decoration、詳細は hover、race は波線と Problems パネル、シナリオモードは右に開くパネルで出します。

5HTML に書き出す

エディタが無くても読める 1 ページです。PR に貼ったり、人に渡したりするときに使います。agent の skill の出力としても、そのまま使えます。

(*Context).Copy の動き

gin @ 35e33d3 · context.go:332–342 · シナリオ 5 本 · go test -race -count=3

行ごと

シナリオ S4 並行

コピーを goroutine に渡したあと、元の Context がプールに戻って次のリクエストに使われる。reset() が Params を書き換えているあいだに、goroutine がコピーから Param() を読むと競合する。S4 ✗ 3/3 回

設計バックエンド：1 つの束を 3 つの出口へ

Rust のコアは「読解の束」という JSON を 1 つ作ります。HTML はその束をテンプレートで描くだけです。エディタには LSP サーバが束を配信します。LSP に元からある部品で足りるところ（race の 2 か所、詳細パネル）はそれを使います。足りないところ（行ごとの説明、シナリオモード）は、独自のリクエストでデータを渡して、エディタ側で描きます。

作る順番

  1. コア crate と CLI。シナリオを実行して束を作り、HTML に書き出す。Rust だけで、Neovim は要らない。
  2. LSP サーバ。同じコアを呼ぶ薄い殻にする。ここで async（tokio）を覚える。
  3. Neovim のプラグイン（Lua）。インライン、詳細パネル、シナリオモードの順に作る。
  4. VS Code の拡張（TypeScript）。typos-lsp と同じく、extension.ts 1 ファイルから始める。
